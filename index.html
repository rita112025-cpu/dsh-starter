DeepSeek Harness 入門模板

準備工作

Node.js

22.19 以上的 22.x，或 24 以上。

到 nodejs.org 下載 LTS 版。檢查版本：node -v

DeepSeek API Key

到 DeepSeek 開放平台申請，格式是 sk- 開頭的一串字。

Key 等同密碼，不要貼到聊天、截圖或公開倉庫。

只從官方來源取得 dsh

npm 套件 @deepseek-ai/dsh，或官方倉庫 github.com/deepseek-ai/deepseek-harness。不要下載來路不明的 .exe 安裝檔。

快速開始

  1. 取得模板

    下載 ZIP

    下載 dsh-starter.zip 並解壓縮，進入 dsh-starter 資料夾。

    Windows「解壓縮全部」預設會多包一層 dsh-starter\dsh-starter，請進看得到 install.bat 的那層。

    用 git clone

    git clone https://github.com/rita112025-cpu/dsh-starter.git
cd dsh-starter

    倉庫根目錄就是模板本身，示例技能可以直接讀到。

  2. 第一次執行啟動腳本

    Windows

    雙擊 install.bat。

    會自動建立 .env 並用記事本打開。

    macOS / Linux

    在資料夾裡打開終端機，執行：

    bash install.sh

  3. 填入 API Key

    把 .env 裡的佔位字串換成你的真實 Key，然後存檔：

    .env
    DEEPSEEK_API_KEY=sk-你的真實Key

  4. 再執行一次啟動腳本

    腳本會檢查 Node.js；還沒安裝 dsh 時會先執行 npm install -g @deepseek-ai/dsh@0.1.5-rc.1，接著啟動 dsh web。

    終端機視窗要保持開著，關掉就等於停止 dsh。要停止時按 Ctrl+C。

  5. 在瀏覽器裡使用

    瀏覽器會自動打開。沒有打開時，看下一節。

打開網頁介面

啟動成功後，終端機會印出一行以 dsh web: 開頭的網址：

終端機輸出範例（實際網址以你的畫面為準）
dsh web: http://127.0.0.1:3080/...（後面帶認證參數）
  • 預設位址是 127.0.0.1:3080。
  • 網址裡帶一次性認證參數，每次啟動都不同。只輸入 127.0.0.1:3080 是進不去的，請複製整行網址。
  • 透過 SSH 連線啟動時，不會自動打開瀏覽器。
3080 被佔用時，dsh 會直接啟動失敗

dsh 不會自動換一個埠號。請改用其他埠號啟動：

dsh web --port 8080

或讓系統自己挑一個空閒的埠號：

dsh web --port 0

試用示例技能

模板內建一個 doc-summary（文件摘要）技能和一份示例文件 workspace/note.md。在網頁介面的對話框輸入：

用 doc-summary 技能总结 workspace/note.md

dsh 會讀完整份文件，輸出「標題、核心用途、關鍵要點、注意事項」四段式摘要。

示例文件是一份虛構的「內部週報系統上線說明」，可以換成你自己的文件試試看。

常用指令

以下指令都要在模板資料夾裡執行，因為 dsh 只會讀取啟動目錄裡的 .env。

指令用途
dsh web啟動網頁介面（等同 dsh --profile web）
dsh web --port 8080指定埠號；--port 0 讓系統挑空閒埠號
dsh web --no-open不要自動打開瀏覽器
dsh web --help網頁介面自己的參數說明
dsh --help啟動器的說明
dsh --profile headless "任務"一次性任務：結果印在終端機後結束，不能接著追問

一次性任務範例

dsh --profile headless "用 doc-summary 技能总结 workspace/note.md"

最終答案輸出到 stdout，思考過程輸出到 stderr；成功時結束代碼為 0，失敗為 1，方便寫進腳本。

不想全域安裝時

npx @deepseek-ai/dsh@0.1.5-rc.1 web

一樣要在模板資料夾裡執行。

目錄結構

dsh-starter/
├── README.md                          簡體中文說明
├── .env.example                       複製成 .env，填 DEEPSEEK_API_KEY
├── .gitignore                         避免 .env 被提交
├── install.bat                        Windows：檢查環境、安裝、啟動
├── install.sh                         macOS / Linux：同上
├── .dsh/
│   └── skills/
│       └── doc-summary/
│           └── SKILL.md               示例技能
└── workspace/
    └── note.md                        示例文件

以 . 開頭的檔案和資料夾（.env.example、.dsh）在 macOS / Linux 預設是隱藏的。Finder 按 Cmd+Shift+. 可以顯示。

啟動腳本做了哪些事

  1. 切換到腳本所在的資料夾
  2. 確認有 Node.js，版本低於 22 時提醒
  3. 沒有 .env 就從 .env.example 複製一份，請你填 Key 後結束
  4. .env 還是佔位 Key 時提醒你修改並結束
  5. 找不到 dsh 指令時執行 npm install -g @deepseek-ai/dsh@0.1.5-rc.1
  6. 建立 workspace 資料夾，執行 dsh web

API Key 與 .env

dsh 依照下面的順序找 DEEPSEEK_API_KEY，先找到的就用：

  1. 1系統或終端機裡的環境變數
  2. 2在 dsh 裡儲存過的 Key：~/.dsh/.credentials.yaml
  3. 3啟動目錄裡的 .env（也就是模板資料夾）
  4. 4使用者目錄的 ~/.dsh/.env
改了 .env 卻沒生效？
  • 先檢查第 1、2 項。環境變數就算設成空值，也會擋住 .env。
  • .env 只讀啟動目錄那一份，不會往上層資料夾找。
  • 改完要重新啟動 dsh。

~ 代表使用者目錄：Windows 是 C:\Users\你的帳號，macOS 是 /Users/你的帳號。.env 不接受 DSH_*、PATH、NODE_OPTIONS 這類變數；代理伺服器相關變數只能寫在 ~/.dsh/.env。

撰寫技能

技能是一份 Markdown 說明書，告訴 dsh 遇到某類任務時該怎麼做。新增或修改後不用重新啟動，會自動生效。

放在哪裡

範圍位置
專案技能<專案根目錄>/.dsh/skills/<名稱>/SKILL.md
個人全域技能~/.dsh/skills/<名稱>/SKILL.md
另外也會讀<專案根目錄>/.agents/skills、~/.agents/skills
「專案根目錄」是最近一個含 .git 的上層資料夾

找不到 .git 才用啟動目錄。所以如果模板資料夾放在某個 git 倉庫的子資料夾裡，請把 .dsh/skills 移到那個倉庫的根目錄，否則技能讀不到。

SKILL.md 格式

.dsh/skills/doc-summary/SKILL.md（開頭部分）
---
name: doc-summary
description: 读取一个文档，输出结构化要点摘要。
whenToUse: 用户要求总结、概括或提炼某个文件的要点时。
---

# 文档摘要

1. 确认要总结的文件路径……
欄位說明
name必填。小寫英文、數字、短橫線，例如 doc-summary
description必填。一句話說明技能做什麼
whenToUse選填。什麼情況該用這個技能
disable-model-invocation選填。不讓模型自己決定呼叫
user-invocable選填。使用者能不能直接呼叫

注意：寫成駝峰式的 disableModelInvocation、userInvocable 會報錯；allowed-tools、argument-hint 不會被讀取。技能也可以寫成單一檔案 <名稱>.md。

工作目錄

啟動 dsh 的資料夾是預設工作目錄。在網頁介面裡，每個對話用的是你在介面中選擇的專案資料夾。

重新產生模板

倉庫裡的 Create-DSH-Starter.ps1 會重新產生整個 dsh-starter 資料夾和 dsh-starter.zip。修改模板內容時，改這支腳本再重跑即可。

建議在倉庫以外的空資料夾執行，再把產生的 ZIP 和模板檔複製回倉庫根目錄，避免倉庫裡多出一層 dsh-starter/。

在腳本所在資料夾執行（Windows PowerShell 5.1 或 PowerShell 7）
powershell -ExecutionPolicy Bypass -File .\Create-DSH-Starter.ps1
  • 輸出位置是目前所在的資料夾，不是腳本所在的資料夾。
  • 已存在的模板檔會被覆蓋；你的 .env 不會被動到。
  • ZIP 只打包腳本產生的 7 個模板檔。試用後留下的 .env、會話資料、個人檔案都不會被打包。
  • 產生的檔案一律是 UTF-8（無 BOM）；install.bat 用 CRLF 換行，其他檔案用 LF。
腳本本身必須存成「UTF-8 with BOM」

否則 Windows PowerShell 5.1 會把中文讀成亂碼，產生出來的檔案內容全錯。用 VS Code 編輯時，右下角編碼選「UTF-8 with BOM」再存檔。

版本與升級

模板鎖定 @deepseek-ai/dsh@0.1.5-rc.1，是 2026 年 9 月 npm 上的 latest 版本，但仍是預發布版，介面可能會變。

版本號只鎖住 dsh 本體

dsh 依賴的數十個 @deepseek-ai/dsh-* 子套件寫的是 ^0.1.5-rc.1 範圍，安裝時會拿到當時最新的相容版本。例如安裝 rc.1 本體，子套件可能是 rc.2。

升級步驟

  1. 執行 npm install -g @deepseek-ai/dsh@新版本號
  2. 把 install.bat 和 install.sh 裡的 DSH_VERSION 改成同一個版本號
  3. 用 dsh web --help 確認參數沒有改變

查看目前有哪些版本：npm view @deepseek-ai/dsh dist-tags

疑難排解

啟動失敗，訊息提到埠號或 address in use

3080 被其他程式佔用了。改用 dsh web --port 8080 或 dsh web --port 0。

瀏覽器顯示無法連線或未授權
  • 確認終端機視窗還開著，dsh 還在執行。
  • 複製終端機裡 dsh web: 那行的完整網址，不要只輸入 IP 和埠號。
  • 重新啟動後網址會變，舊書籤不能用。
提示找不到 API Key，或 Key 無效
  • 確認 .env 已存檔，而且是在模板資料夾裡啟動。
  • 依照 優先順序 檢查環境變數和 ~/.dsh/.credentials.yaml。
  • 確認 Key 前後沒有多餘的空白或引號。
剛安裝完 dsh，卻顯示找不到 dsh 指令

新安裝的指令有時要重開終端機才找得到。Windows 請關掉視窗後重新雙擊 install.bat；macOS / Linux 請開新的終端機再執行。

macOS / Linux 安裝時出現 EACCES 權限錯誤

npm 的全域目錄沒有寫入權限。建議改用 nvm 安裝 Node.js，或把 npm 全域目錄設到使用者目錄，不建議直接用 sudo。

示例技能沒有出現
  • 確認 .dsh/skills/doc-summary/SKILL.md 存在（.dsh 是隱藏資料夾）。
  • 模板資料夾是不是放在某個 git 倉庫裡？請看 專案根目錄 的說明。
  • 確認 SKILL.md 開頭有 name 和 description，name 只用小寫英文、數字和短橫線。
macOS 上 install.sh 無法雙擊執行

ZIP 不會保留執行權限，這是正常的。請在終端機用 bash install.sh 執行。

執行 Create-DSH-Starter.ps1 後，檔案內容是亂碼

腳本檔沒有存成「UTF-8 with BOM」。用 VS Code 重新以該編碼存檔，再執行一次。

安全須知

.env 裡是你的 API Key
  • 不要提交到 git（模板的 .gitignore 已經排除它）。
  • 不要傳給別人、不要貼到聊天或截圖。
  • Key 外洩時，立刻到 DeepSeek 開放平台作廢並重新申請。
  • 產生器打包的 ZIP 只含模板檔，可以放心分享。直接分享資料夾之前，請自己檢查裡面有沒有 .env 或私人檔案。
  • dsh 能讀寫工作目錄裡的檔案、執行指令。請在你信任的資料夾裡使用，不要直接在整個使用者目錄或系統磁碟根目錄啟動。
  • 只從 npm 或官方 GitHub 取得 dsh。
